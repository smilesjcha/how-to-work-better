# 강의 PPT 제작 플레이북

## 출발점: 장표보다 수업 설계

이 문서는 특정 브랜드의 모양을 복제하는 템플릿이 아니다. 수강생이 무엇을 **이해·수행·검수**할지에 따라 정보 구조를 고르는 기준이다. 제작 전에는 대상(직군·선행 지식·장비), 학습 산출물, 설문과 업무 증거, 강의/실습/휴식의 큰 구간, 실습 입력과 완료 기준, 공개 가능 정보의 경계를 적는다.

| 장표의 역할 | 수강생의 질문 | 적합한 화면 | 피할 화면 |
|---|---|---|---|
| 방향 | 오늘 무엇을 얻나? | 산출물·큰 시간 블록 | 1분 단위 시간표 |
| 이해 | 왜 그렇게 판단하나? | 대조·근거–주장·절차 | 같은 3카드 반복 |
| 수행 | 어디에 무엇을 넣나? | 원문·작업지·완료 기준 | 따라 할 수 없는 개념도 |
| 검수 | 맞는지 어떻게 아나? | 계산식·반례·원자료 대조 | ‘AI가 확인’이라는 추상어 |

## ToT식 구성 선택

[Tree of Thoughts 논문](https://proceedings.neurips.cc/paper_files/paper/2023/file/271db9922b8d1f4dd7aaef84ed5ac703-Paper-Conference.pdf)은 여러 중간 경로를 탐색·평가하는 문제 해결 프레임이다. 여기서는 그 발상을 **디자인 의사결정의 비유**로만 쓴다. 논문이 특정 PPT 레이아웃의 효능을 입증했다는 의미는 아니다.

```text
수업 기능 → 자료 구조 → 학습 행동 → 후보 구성 2–3개 → 평가 → 선택

방향 제시 → 목표/시간표      → 기억     → 선언형 / 로드맵 / 큰 시간 블록
개념 이해 → 3요소/차이/순서  → 구분     → 인덱스 / 대조 / 열린 레일
증거 해석 → 수치/표/원문      → 판단     → 순위 / 막대 / 원문+주석
실습 수행 → 절차/프롬프트     → 따라 하기 → 작업지 / 경로 / 원문 facsimile
검수 훈련 → 오류/기준/반례     → 대조     → 전후 비교 / 검수표 / 오류 위치
```

후보별로 다음을 0–2점으로 평가한다: ① 핵심이 한눈에 보이는가 ② 모든 요소가 학습에 필요한가 ③ 재현 가능한가 ④ 내용 밀도에 맞는가 ⑤ 앞뒤 장표와 모양이 덜 겹치는가 ⑥ 출처와 의미가 분명한가. 동점이면 시각 리듬이 덜 반복되는 구성을 선택한다. 코드의 `type`(내용 종류)과 `composition`(표현 방식)은 분리하고, 중요한 장표는 사람이 구성을 명시한다.

## 구성 레퍼토리

| 내용 | 첫 후보 | 대체 후보 | 통합 판단 |
|---|---|---|---|
| 세 개 개념 | 번호+가로 근거 | 3열 편집형·한 항목 강조 | 셋이 같은 결론을 반복하는가? |
| A/B 비교 | 좌우 대비 | 기준별 병렬·판정문 | 기준과 결론을 한 장에 넣을 수 있는가? |
| 4–5단계 절차 | 열린 레일 | 세로 계단·작업지 | 설명과 수행 순서가 중복되는가? |
| 표 | 열린 행 | 옅은 밴드·첫 열 강조 행렬 | 같은 값의 다른 관점뿐인가? |
| 설문 수치 | 가장 큰 응답+나머지 순위 | 단순 막대 | 수치 비교가 새 메시지를 만드는가? |
| 프롬프트 | 줄번호 있는 원문 | 실제 구조 주석 | 요청과 해설이 중복되는가? |
| 실습 | 완료 기준 중심 작업지 | 단계 경로·점검 목록 | 별도 절차장이 필요한가? |
| 원문/이미지 | 큰 원문+인접 해석 | 확대 캡처+단일 강조 | 강의실에서 원문이 읽히는가? |

### 표와 계층

- **원장·검산**: 행을 따라 근거를 확인한다. 열린 가로선, 고정된 단위, 명시적 합계를 쓴다.
- **선택·비교**: 후보가 적으면 기준별 병렬이 표보다 빠를 수 있다.
- **밀집 데이터**: 5열 이상이면 첫 열과 머리글만 조용히 구분한다. 진한 띠와 모든 셀 테두리는 피한다.
- **두 시점 변화**: 변화값을 크게 보이고 계산식·분모를 가까이 둔다.
- **원문 표**: 출처·페이지·적용 범위를 주석으로 남긴다.

## 글·서체·이미지

제목과 부제는 주제 중심 명사구, 본문은 동사와 조건이 있는 문장으로 쓴다. ‘혁신적·스마트한·완벽한’ 같은 수식어를 제거한다. 서체는 설치·배포 환경에서 열리는 한국어 산세리프를 고른다. 브랜드 전용 서체를 확인 없이 사용한다고 주장하지 않는다. [Microsoft의 PPT 가이드](https://support.microsoft.com/en-us/powerpoint/tips-for-creating-and-delivering-an-effective-presentation)는 단순한 메시지, 읽기 쉬운 서체, 명료한 그래프를 권한다.

이미지는 증거·실제 절차·현장 맥락을 전달할 때만 사용한다. 무관한 스톡 사진은 빼고, 캡처는 원문 위치·날짜·권리 상태를 기록한다. 글과 그림을 인접하게 놓고 학습과 무관한 요소를 줄이는 기준은 [Mayer의 멀티미디어 학습 원칙](https://www.benjamins.com/catalog/dd.1.1.02may) 및 [후속 정리](https://www.cambridge.org/core/books/abs/cambridge-handbook-of-multimedia-learning/principles-for-reducing-extraneous-processing-in-multimedia-learning-coherence-signaling-redundancy-spatial-contiguity-and-temporal-contiguity-principles/C98AB3A6CE760DD63C048936EA0B3B44)와 연결된다.

## 코드 구조와 완료 기준

`slides_data.py`(내용·출처·발표자 노트), `composition.py`(구성 선택), `theme.py`(색·서체·간격), `layouts.py`(도형 배치), `build.py`(출력), `qa_deck.py`(검수)를 분리한다. 레이아웃 코드에 색·좌표·강의 문구를 뒤섞지 않는다.

1. 제목 중복, 빈 화면, 슬라이드 밖 도형, 연속 3장 같은 구성, 출처 누락을 검사한다.
2. PPTX를 실제 오피스 렌더러로 PDF 변환하고 **전 페이지** 콘택트시트를 본다.
3. 표의 긴 셀, 프롬프트, 스크린샷, 사진, 마지막 Q&A를 확대 검수한다.
4. 숫자·산식·기간·단위를 원자료로 재확인한다. 실습 데이터에 실제 개인정보·비공개 기업 수치를 넣지 않는다.
5. PPTX와 PDF의 줄바꿈을 비교한다. 수강생 자료는 입력/작업/결과/정답 예시를 분리하고, 설치·계정이 없는 사람의 대체 경로를 둔다.

삭제 기준은 단순하다. “이 장표를 지우면 학습 결과가 달라지는가?” 달라지지 않으면 합치거나 삭제한다. “수강생이 이 장표만 보고 다음 행동을 시작할 수 있는가?” 아니라면 입력·예시·완료 기준을 보강한다.
