# 문서 양식 확장과 본문 정리

## 수정 기준

- 93장 프롬프트는 실제 줄바꿈을 측정해 행 높이를 배정한다. 행 구분선이 문장을 가로지르면 빌드 검수 실패로 본다.
- 소개는 이름 → 현재 역할 → 담당 제품·사업의 계층으로 나눈다. 사진 제공자·이력 확인 방식·제작 조건은 발표자 노트에만 둔다.
- 실습은 전 과정 1인 개별 수행. 장비·로그인이 없으면 본인 인쇄물에 직접 계산·기입한다.
- Codex와 Claude Code는 도구 순위를 비교하지 않는다. 같은 파일 작업의 선택 가능한 실행 도구로만 소개한다.

## 문서의 경계

최종 보고서는 독자의 판단을 돕는 결론·근거·요청·실행 사항을 담는다. AI에게 보낸 지시, 수정 횟수, 대화 중의 합의, 형식 선택 이유는 작업 기록으로 분리한다. 단, 사업 의사결정의 실제 이유·필수 승인 이력·규정상 보존 대상은 삭제하지 않는다. 공식 문서의 성격에 따라 본문·부록·별도 기록으로 보존한다.

## 연결 사례

가상 회사 한빛유업의 동일한 판매·반품 원자료를 사용한다.

| 양식 | 독자 질문 | 보여 줄 구성 |
| --- | --- | --- |
| 데이터 요약표 | 무엇이 변했나? | 전월·당월·차이·단위·확인 사항 |
| 1페이지 보고서 | 무엇을 결정해야 하나? | 조사 승인 요청·핵심 수치·미확인·다음 행동 |
| WBS·Gantt | 누가 언제 무엇을 끝내나? | 작업·담당 역할·선행 작업·산출물·기간 |
| 임원 제안서 2pager | 왜 시작하고 어디까지 승인하나? | 문제·해결안 / 파일럿·성공 조건·위험·승인 |
| PRD | 무엇을 만들고 어떻게 합격시키나? | 사용자·범위·흐름 / 요구사항·예외·인수 조건 |
| 운영 대시보드 | 어느 신호에 어떤 행동이 필요한가? | 핵심 지표·제품별 차이·추가 확인·업데이트 기준 |

원자료의 관측값과 파일럿의 제안 목표를 명확히 분리한다. 원자료에 없는 담당·기한·원인은 확정하지 않는다. WBS의 일정과 서비스 제안의 성공 조건은 교육용 계획 예시다.

## 표현

요약표는 편집 가능한 숫자 표, WBS는 작업 표와 기간 막대, 보고서는 결론 띠와 근거·행동, 제안서는 두 페이지의 문제/실행 분리, PRD는 흐름과 인수 조건, 대시보드는 지표·달성률·조치 큐로 표현한다. 동일한 카드나 도식으로 양식을 반복하지 않는다.

모든 크기·색·서체·간격은 `theme.py`로 관리한다. 문서 예시와 프롬프트는 2부의 선택형 확장으로 사용한다. 필수 실습 A/B/C와 두 번의 90분 수업은 그대로 유지한다.
