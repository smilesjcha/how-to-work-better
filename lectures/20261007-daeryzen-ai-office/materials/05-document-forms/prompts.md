# 문서 유형별 작성 프롬프트

## 공통 입력과 출력 경계

검산된 요약표와 선택한 양식만 사용하세요. 관측 사실·제안 목표·미확인을 나누고 새 수치·출처·원인·담당·기한을 만들지 마세요. 최종 문서에는 독자의 판단과 실행에 필요한 내용만 남기세요. 작성 지시·수정 이력·대화 중 합의는 별도 작업 기록으로 분리하세요. 필요한 사실 출처·결정 이유·승인 조건은 유지하세요.

## 데이터 요약표

월간 CSV와 목표표를 검산해 제품별 판매·목표·차이·달성률·반품 접수·접수 건수÷판매 개수 비율을 표로 작성하세요. 제품별 행 뒤에 합계 행을 넣고 전체 비율은 합계로 계산하세요. 전월 변화와 미확인 항목은 표 아래에 구분하세요. 기간·단위를 헤더에 표시하고 숫자는 같은 자릿수로 정렬하세요.

## WBS·Gantt

4주 파일럿 계획을 작업·담당 역할·선행 작업·시작·종료·완료 산출물로 나누세요. 일정은 제안임을 표시하고 선행 작업 종료 전에 후속 작업이 시작하지 않게 검증하세요. WBS 표를 확정한 뒤 주차별 Gantt를 그리세요. 완료 기준에 수치 검산·사용자 검토·사람 승인을 포함하세요. 일정 지연 시 영향받는 후속 작업을 별도 목록으로 정리하세요.

## 임원 제안서 2pager

`executive-two-pager.md` 구조로 서비스 제안서를 작성하세요. 1페이지는 승인 요청·현재 문제·해결안·사용자·범위 제외, 2페이지는 파일럿·인수 목표·위험·자원·승인 항목입니다. 검증된 현재 값과 제안 목표를 구분하세요. 소요시간·비용·효과가 입력에 없으면 산정 필요로 남기세요. 수정 이유나 “요청에 따라 추가했다” 같은 문장은 넣지 마세요.

## PRD

`service-prd.md` 구조로 제품 기획서를 작성하세요. 요구사항별 ID, 사용자 문제, 기능, 예외, 검증 가능한 인수 조건을 연결하세요. 정상 입력뿐 아니라 필수 열 누락·값 누락·중복·판매 0개·담당 미정·미승인 상태의 동작을 정의하세요. 원자료 읽기 전용, 작업 기록과 결과물 분리, 승인 전 외부 발송 차단을 포함하세요. 미정 사항을 결정된 요구사항처럼 쓰지 마세요.

## 대시보드

상단에 판매·전체 달성률·반품 비율, 중단에 제품별 달성률과 100% 기준선, 하단에 신호·추가 자료·다음 행동을 배치하세요. 지표마다 기간·단위·분자·분모·갱신 기준을 별도 정의표에 기록하세요. 두 달로 장기 추세·인과관계를 단정하지 말고 색상을 제품 안전성 등급으로 사용하지 마세요.

## 최종 본문 정리

아래 초안을 제출용 본문으로 정리하세요. 결론·핵심 수치·사실 근거·필요한 결정 이유·실행 사항은 보존하세요. AI에 보낸 지시, 수정 횟수, 형식 변경 설명, 대화 중의 합의는 본문에서 제외하세요. 다만 문서 목적상 필요한 승인 이력·미확인·판단 조건은 삭제하지 마세요. 최종 본문만 출력하고 수정 설명과 검수 질문은 별도 작업 파일로 작성하세요.
